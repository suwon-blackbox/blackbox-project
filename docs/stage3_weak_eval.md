# Stage 3 약한 정답 평가 (AI Hub)

## 왜 필요한가

Stage 3 정답(0.1초 단위 가속/감속/정속 × 좌/우/직진)은 센서가 있는 comma2k19에서만 만들 수 있다.
그런데 실제로 분석할 영상은 한국 블랙박스 영상이다. **comma로 학습한 모델이 한국 영상에서도 통하는지**를
확인하려고, AI Hub에 이미 있는 사고유형 글로 영상 단위의 "대략적인 기대값"을 만든다.

## 어떻게 만드나 (사람 작업 없음)

1인칭 영상에서는 내 차 = 사고객체 B (데이터설명서 19쪽). B 진행정보 154종을 규칙으로 분류했다.

| 신뢰도 | B 진행정보 예 | 기대값 | 영상 수 (전체) |
|---|---|---|---|
| high | 좌회전, 유턴 | 충돌 직전 **좌** | 1,619 |
| high | 우회전 | 충돌 직전 **우** | 1,044 |
| high | 주(정)차, 정차중 | **정속·직진** (멈춰 있음) | 204 |
| high | 정차 후 출발 | **가속·직진** | 9 |
| medium | 직진 | **직진** (작은 조향이 섞일 수 있음) | 5,459 |
| exclude | 진로변경, 추월, 합류, 회전교차로, 후진, "또는" | 쓰지 않음 | 7,304 |

- 매핑표: [configs/stage3_weak_map.csv](../configs/stage3_weak_map.csv). **틀린 줄은 손으로 고치면 된다** (다시 실행해도 유지됨)
- "직진(직진·우회전 노면표시차로)"처럼 괄호 안의 차로 표시는 움직임으로 보지 않는다
- 가속·감속은 글에 거의 안 나와서 종방향은 정지·출발 영상만 확인할 수 있다

```bash
python scripts/make_weak_labels.py --extract
```

## 어떻게 평가하나

- **0.1초마다 비교하지 않는다.** 충돌 직전 구간(3.0~5.0초, AI Hub 클립은 사고 시점 앞뒤 5초)에서
  기대 라벨이 50% 이상 나오면 그 영상은 맞음
- 직진이 대부분이라 **클래스별 정답률의 평균(균형 정답률)**을 대표값으로 쓴다
- 기본은 test 분할(1,728건)만 평가한다

```bash
python scripts/eval_stage3_weak.py --pred-dir outputs/aihub
python scripts/eval_stage3_weak.py --baseline straight    # 비교 기준: 좌우 균형 정답률 33.3%
```

## 약한 정답이 틀렸을 때 → 사람 점검 50건

약한 정답에는 틀린 것이 섞여 있다. **얼마나 틀렸는지를 직접 재서 점수를 해석한다.**

1. `data/splits/stage3_weak_check.csv` (test에서 고른 50건, 1인당 25건)
2. 영상은 `data/raw/stage3_weak_check/`
3. 충돌 직전 2초(3~5초)를 보고 `check_result`에 적는다
   - `yes`: 기대값대로 움직였다 (예: 기대 '좌'인데 실제로 좌회전 중)
   - `no`: 다르게 움직였다 → `memo`에 실제 움직임
   - `unclear`: 판단 불가 (계산에서 빠짐)
4. 1건에 1분 정도. 프레임을 찍는 라벨링이 아니다

채운 뒤 평가를 다시 돌리면 "약한 정답의 정확도"가 함께 나온다.

## 점수 해석

| 상황 | 해석 |
|---|---|
| 약한 정답 정확도 90%, 모델 85% | 거의 한계까지 맞힘 |
| 약한 정답 정확도 90%, 모델 50% | 한국 영상에서 잘 안 통함 → 입력 맞추기·자기 학습 필요 |
| 모델 A 72% vs 모델 B 81% | 정답 오류는 두 모델에 똑같이 작용 → **B가 낫다고 판단해도 됨** |

**절대 점수보다 모델끼리 비교하는 데 쓴다.** 정확한 0.1초 성능은 comma2k19 test와 직접 주행 기록으로 잰다.
